Section 5.6 · Sample data and verification

Loads the sample data from the proposal and tries to break each rule. Everything runs inside one transaction that is rolled back, so the live data is untouched.

Experiment 1 · Double booking

Creates N rides for the same slot and fires N simultaneous “accept” transactions for one driver, each on its own connection.

Experiment 3 · Concurrent matching

R riders and D drivers request at the same instant using the matching query with FOR UPDATE SKIP LOCKED.

Experiment 4 · Spatial index

EXPLAIN ANALYZE of the matching query over 20,000 drivers, without and with the GiST index on drivers.location (rolled back afterwards).

Experiment 5 · Isolation levels

The accept-ride transaction, 50 at once, under READ COMMITTED and SERIALIZABLE.

Experiment 6 · Crash recovery

Start a ride in the app, stop the server (Ctrl+C) and start it again. The ride comes back in the same status, because no ride state is held in server memory; only the socket map is.
